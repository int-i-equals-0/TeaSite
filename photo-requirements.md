# Требования к фотографиям

Этот документ нужен, чтобы фотографии можно было добавлять в проект без переименований и ручной подгонки в коде.

## 1. Общий принцип

Фотографии должны помогать выбрать чай, а не создавать абстрактную атмосферу. Пользователь должен видеть товар, лист, настой, посуду и масштаб.

Стиль:

- спокойный;
- чистый;
- без псевдовосточного реквизита;
- без доминирования коричневого фона;
- без жестких теней;
- без перегруженного окружения.

Подходящие фоны:

- бледно-зеленый;
- теплый светло-серый;
- нейтральный матовый;
- мягкая каменная или керамическая поверхность без активного рисунка.

Нежелательные фоны:

- чистый белый;
- глянцевый черный;
- темное дерево как основной фон;
- бежево-кофейная палитра как доминанта;
- яркий тканевый фон;
- пестрые "чайно-восточные" декорации.

## 2. Папки

Базовая папка для товаров:

```text
assets/images/products/
```

Для каждого товара создается отдельная папка по его `slug` из JSON:

```text
assets/images/products/ali-shan-gaba-oolong/
```

Пример:

```text
assets/images/products/
  ali-shan-gaba-oolong/
    main.webp
    leaf.webp
    infusion.webp
    pack.webp
```

Для чайной посуды:

```text
assets/images/products/glass-gaiwan-150/
  main.webp
  angle.webp
  scale.webp
```

Плейсхолдеры:

```text
assets/images/placeholders/
  tea-default.svg
  teaware-default.svg
```

Если изображения товара нет, сайт должен показывать плейсхолдер.

## 3. Именование файлов

Файлы называются только латиницей, в нижнем регистре, через дефис.

Разрешено:

```text
main.webp
leaf.webp
infusion.webp
pack.webp
detail.webp
angle.webp
scale.webp
```

Не использовать:

```text
Габа улун фото 1.jpg
IMG_4321.JPG
photo final final.png
ali shan.jpeg
```

Кириллицу, пробелы и спецсимволы в именах файлов не использовать.

## 4. Минимальный набор для чая

Для каждого чая обязателен один файл:

```text
main.webp
```

Желательный набор:

- `main.webp`: главный кадр для каталога и карточки товара;
- `leaf.webp`: сухой лист крупнее;
- `infusion.webp`: настой в чашке или пиале;
- `pack.webp`: упаковка или фасовка;
- `detail.webp`: дополнительный красивый или информативный кадр.

Если времени мало, сначала достаточно `main.webp`. Остальные файлы можно добавлять позже.

## 5. Минимальный набор для посуды

Для каждой позиции чайной посуды обязателен:

```text
main.webp
```

Желательный набор:

- `main.webp`: предмет целиком;
- `angle.webp`: вид под углом;
- `scale.webp`: предмет рядом с чашкой, рукой или другим понятным объектом масштаба;
- `detail.webp`: фактура, носик, крышка, сито, ручка или другой важный элемент.

## 6. Размеры

Основной формат для товарных фото:

- соотношение сторон: 4:3;
- рекомендуемый размер: 1200 x 900 px;
- минимальный размер: 900 x 675 px;
- формат: WebP;
- цветовой профиль: sRGB.

Допустимый вес:

- желательно до 350 KB на изображение;
- максимум до 600 KB, если кадр действительно важен.

Для исходников можно хранить большие версии отдельно, но в сайт должны попадать оптимизированные файлы.

## 7. Кадрирование

Для `main.webp`:

- товар должен быть в центре;
- вокруг товара нужен воздух;
- важные части не должны упираться в края;
- кадр должен хорошо обрезаться в карточке каталога;
- не помещать текст поверх фото.

Для `leaf.webp`:

- лист должен быть различим;
- лучше показать фактуру, скрутку, цвет;
- не делать слишком сильное макро, где непонятен общий вид.

Для `infusion.webp`:

- настой должен показывать цвет;
- чашка или пиала должны быть чистыми и нейтральными;
- не затемнять жидкость драматичным светом.

Для `pack.webp`:

- упаковка должна быть читаемой, если на ней есть текст;
- не делать слишком сильную перспективу;
- не использовать кадр, где упаковка выглядит мятой или случайной.

## 8. Свет

Лучше использовать мягкий боковой или рассеянный дневной свет.

Избегать:

- резкого прямого солнца;
- желтого комнатного света;
- сильных бликов;
- жесткой тени от чашки или упаковки;
- смешанного освещения разной температуры.

Если есть возможность, лучше снимать все товары в одной световой схеме. Так каталог будет выглядеть цельно.

## 9. Цвет

Цвет чая и настоя должен быть правдоподобным. Не стоит выкручивать насыщенность ради "вкусной картинки", если из-за этого зеленый чай становится кислотным, а красный чай выглядит как кофе.

Обработка допустима:

- выровнять экспозицию;
- убрать лишнюю желтизну;
- слегка поднять контраст;
- убрать пыль или мелкий мусор.

Обработка нежелательна:

- сильные фильтры;
- виньетки;
- искусственное размытие;
- чрезмерная резкость;
- неестественное изменение цвета настоя.

## 10. Alt-тексты

В JSON для каждого изображения должен быть `alt`.

Хороший alt:

```text
Сухой лист габа улуна Алишань на светло-зеленой поверхности
```

Плохой alt:

```text
Фото
Картинка чая
Красиво
```

Для главного изображения обычно достаточно:

```text
Габа улун Алишань, сухой лист и чашка настоя
```

## 11. Связь с JSON

В JSON товар ссылается на изображения так:

```json
{
  "images": {
    "main": "assets/images/products/ali-shan-gaba-oolong/main.webp",
    "leaf": "assets/images/products/ali-shan-gaba-oolong/leaf.webp",
    "infusion": "assets/images/products/ali-shan-gaba-oolong/infusion.webp",
    "pack": "assets/images/products/ali-shan-gaba-oolong/pack.webp"
  },
  "imageAlt": {
    "main": "Габа улун Алишань, сухой лист и чашка настоя",
    "leaf": "Сухой лист габа улуна Алишань",
    "infusion": "Настой габа улуна Алишань в пиале",
    "pack": "Упаковка габа улуна Алишань"
  }
}
```

Если есть только `main.webp`, остальные поля можно не указывать.

## 12. Видео

Для демки достаточно статического блока под будущее видео.

Если видео появится позже, предлагаемый путь:

```text
assets/video/brewing/
  basic-gaiwan-brewing.mp4
  basic-gaiwan-brewing.webp
```

Где:

- `.mp4` - само видео;
- `.webp` - постер видео.

Видео не является обязательным для MVP.

## 13. Чеклист перед добавлением фото

- Файл в WebP.
- Размер около 1200 x 900 px.
- Соотношение сторон 4:3.
- Название файла латиницей.
- Папка совпадает со `slug` товара.
- Главный кадр называется `main.webp`.
- Нет чистого белого фона как доминанты.
- Нет жестких теней и желтого света.
- Товар хорошо читается в маленькой карточке.
- В JSON добавлен нормальный `alt`.
